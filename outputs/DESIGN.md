# Qoder Team Space — 产品设计说明

## 定位与愿景

Qoder Team Space 是 Qoder IDE 内置的"团队空间"模块，让多人协作团队能够在熟悉的 IDE 环境中完成 Agent 协作、任务管理、知识沉淀等一系列团队工作，无需切换到外部工具。

核心价值主张：**人与多个 AI Agent 在同一个项目中协同工作，Agent 既是执行者也是团队成员。**

---

## 架构概览

```
┌──────────────────────────────────────────────────────────────┐
│ IDE 顶栏：仓库信息 / 项目切换器 / 分支 / 协作头像            │
├────────┬───────────────────────────────────────┬─────────────┤
│ 侧边栏 │            中心内容区                  │  右侧面板    │
│        │                                       │ (260px)     │
│ 代码   │  根据侧边栏 Tab 和团队导航切换视图：    │             │
│ Issues │  - 项目进展 (ProjectProgress)          │ 上下文信息  │
│ PR     │  - 项目待办 (TodoView)                 │ Agent 状态  │
│ 团队空间│  - Agent 协作 (AgentChat)              │ 待确认事项  │
│        │  - 知识库 (KnowledgeBase)              │ 项目快照    │
│        │  - 配置与资产 (ConfigView)              │             │
├────────┴───────────────────────────────────────┴─────────────┤
│ 共享数据层 (src/data.ts) — Agent / 成员 / 项目 / 待确认      │
└──────────────────────────────────────────────────────────────┘
```

采用三栏 IDE 布局，团队空间作为侧边栏的一个 Tab 存在，与代码、Issues、PR 平级。这确保了功能的可发现性，同时不破坏已有的 IDE 工作流。

## 导航结构（精简后）

将原始 7 个导航项精简为 5 个，避免信息过载：

| 导航项 | 说明 | 设计理由 |
|--------|------|----------|
| 项目进展 | 甘特图式的里程碑总览 | 作为进入团队空间后的首屏，提供全局感知 |
| 项目待办 | 人 + Agent 的任务列表 | 按段控切换筛选，不做多级嵌套 |
| Agent 协作 | IM 式对话，群聊+私聊 | 核心交互入口，替代旧的 Tab 切换模式 |
| 知识库 | Agent 产物 + 人工文档 | 支持按 Agent 筛选，自动同步标记 |
| 配置与资产 | Agent 资产 + 权限管理 | 合并低频页面，减少导航噪声 |

被合并或移除的原始页面：Agents（合并到配置）、Members（信息融入各处头像）、Permissions（合并到配置）、AgentAssets（合并到配置）、Deploy（移除，生产部署属于 CI/CD 范畴）。

## 核心设计决策

### 1. Agent 协作 — 对话列表模式（重点改造）

**旧方案问题**：用 "多 Agent 协作 / 单 Agent" 两个 Tab 切换，存在三个明显缺陷：

- 切换后内容无差异感知 —— 用户看不出群聊和私聊的区别
- 单 Agent 模式缺少返回入口 —— 没有从私聊回到群聊的路径
- 不能在当前上下文直接输入 —— Tab 只展示历史记录

**新方案**：借鉴 WeChat / Slack 的对话列表范式：

```
┌─────────────────────────────────────────────────┐
│ 对话列表(200px) │      活动对话内容区             │
│                 │                                │
│ 👥 全员群聊     │ ← 返回群聊 (仅私聊显示)         │
│ 🎨 前端 Agent   │ 📢 群聊提示 / 💬 私聊提示       │
│ ⚙️ 后端 Agent   │                                │
│ 🧠 算法 Agent   │ [消息流 + 工作产物卡片]         │
│ 📋 产品 Agent   │                                │
│                 │ ┌──────────────────────┐       │
│ ─ Agent 任务 ── │ │ 输入区（上下文感知）   │       │
│ 🎨 组件开发 ●   │ └──────────────────────┘       │
│ ⚙️ 接口+缓存 ◎  │                                │
└─────────────────────────────────────────────────┘
```

改进点：
- 左侧对话列表一目了然地区分群聊和各 Agent 私聊
- 每个对话有完全独立的消息内容，切换后差异明显
- 私聊顶部提供"← 返回群聊"按钮
- 输入区 placeholder 根据当前对话上下文变化
- 群聊中可见所有 Agent 的相互对话和工作产物
- 私聊中只看到你和该 Agent 的交流

### 2. 共享数据层

所有视图从 `src/data.ts` 导入 Agent、成员、项目、待确认等数据，消除了数据定义散落在各组件中的问题。好处：

- 单一数据源，修改一处全局生效
- 类型安全，接口定义统一
- 便于后续接入真实 API（只需替换 data.ts 的导出）

### 3. 全局右侧面板 vs 视图内面板

**决策**：只保留 IDE 全局的 RightPanel (260px)，不再允许视图内部自行创建侧面板。

**原因**：AgentChat 曾有自己的 300px 侧面板，与 IDE 的 260px RightPanel 并存导致布局压缩和信息重复。统一使用一个面板后，中心内容区空间更充裕，信息层级更清晰。

### 4. Todo 筛选简化

**旧方案**：状态(全部/待处理/进行中/已完成) × 类型(人/Agent) = 多达 15 种组合，认知负荷过高。

**新方案**：单维度段控 (Segment Control)，4 个互斥选项：全部 / 待我处理 / 人的任务 / Agent 任务。用最少的交互覆盖最常见的筛选场景。

### 5. 配置合并

将"权限管理"和"Agent 资产"合并为 `ConfigView`，通过顶部 Tab 切换：

- **Agent 资产** Tab：选择 Agent → 查看/编辑 System Prompt、Skills、Workflows、Memory
- **权限与审批** Tab：审批规则表 + Agent 权限边界矩阵

这两个功能都属于低频管理操作，合并减少导航复杂度。

## 模块详解

### ProjectProgress（项目进展）

展示当前项目的里程碑进度、关键指标和 Agent 贡献统计。作为团队空间首页，帮助成员快速了解项目全貌。

### TodoView（项目待办）

分为两种视觉形式：
- **人的任务**：卡片式展示，包含背景说明、参考资料链接、具体待做事项清单
- **Agent 任务**：紧凑表格，展示执行进度和状态

设计意图：人的任务需要更多上下文才能决策，所以用富卡片；Agent 任务重在批量监控，所以用表格。

### AgentChat（Agent 协作）

见上文"对话列表模式"设计决策。

额外设计细节：
- 工作产物（Artifact）嵌入在消息流中，点击展开完整预览
- 产物带"已入库"标记，表示已自动同步至知识库
- Agent 之间的 @提及显示为 `→ 🎨 前端 Agent` 的引用样式
- 待确认事项以顶栏按钮入口展示，点击弹出审批面板

### KnowledgeBase（知识库）

支持三维度浏览：
- 来源类型：Agent 产物 / 个人产物 / 人+Agent 协作
- Agent 筛选：查看特定 Agent 产出的所有文档
- AI 整理：自动去重、生成摘要、标记过时内容

### ConfigView（配置与资产）

Agent 资产部分：每个 Agent 的 System Prompt 可在线编辑保存，Skills/Workflows/Memory 以卡片网格展示，清晰呈现 Agent 的能力边界。

权限部分：定义哪些操作可自主执行、哪些需人工审批。以双表格（审批规则 + 能力边界）呈现，让管理者一目了然。

## 技术栈

- **框架**：React 18 + TypeScript (严格模式)
- **构建**：Vite 6
- **状态管理**：组件内 useState（Demo 规模无需外部状态库）
- **样式**：纯 CSS (index.css)，CSS Variables 控制主题
- **组件库**：自建 `components/shared.tsx`（Avatar、Tag、Modal 等基础组件）
- **数据层**：`src/data.ts`（可替换为 API 调用）

## 重构记录

本次重构解决了 6 个核心问题：

1. **双侧面板冲突** — AgentChat 内部 300px 面板 + IDE 全局 260px 面板导致中心区过窄 → 移除视图内面板
2. **数据散落** — Agent/成员定义在 4+ 个文件中重复 → 抽取 data.ts
3. **导航臃肿** — 7 个 Nav 项导致选择困难 → 精简为 5 个
4. **冗余信息栏** — project-context-bar 与 ProjectProgress 信息重复 → 移除冗余栏
5. **Todo 筛选过于复杂** — 15 种组合 → 4 个互斥段控
6. **Agent 协作模式切换不直观** — Tab 切换无内容差异 → 对话列表模式（群聊 + 私聊）
