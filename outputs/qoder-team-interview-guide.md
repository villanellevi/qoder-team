# Qoder Team — 面试讲解指南

## 开场：我对 Qoder 产品方向的理解

Qoder 现在在做的是 **Agentic Coding**：让 AI 不只是补全代码，而是真正理解目标、拆任务、改代码、跑验证、交付结果。

我认为这个能力一旦跑通，就不应该只停留在开发者这一个人群。我的 Demo 展示的是这个能力的三个延伸方向：

1. **多人 + 多 Agent 协作**：团队里的每个人都有自己的 Agent，Agent 之间能自动沟通和协作
2. **共享知识库**：本地文件私密，团队文件共享，知识在 Agent 和人之间流动
3. **自动部署与验证**：Agent 自动完成部署、测试、性能监控，人只需要确认最终结果

---

## Demo 讲解路线（建议 15-20 分钟）

### 第一步：工作台首页（2 分钟）

**要讲什么**：
- 展示"本地空间 vs 团队空间"的设计，体现**权限分层**的思路
- 展示团队动态，体现**Agent 是团队的一部分**，而不只是工具
- 核心数据卡片：知识库数量、活跃 Agent、待确认任务、部署次数

**关键话术**：
> "Qoder 现在做的是让开发者指挥一个 AI。我做的是让团队里的每个人指挥自己的 Agent，Agent 之间自动协作。本地文件保持私密，团队文件共享，这就是'团队版'的基础。"

### 第二步：团队知识库（3 分钟）

**要讲什么**：
- 多人共同维护文档，有版本、贡献者、更新记录
- 支持 @Agent 让 AI 帮忙整理知识库（去重、生成摘要、检查过时内容）
- 文档分类：API 文档、代码片段、最佳实践

**关键话术**：
> "知识库不只是存文档的地方，它是 Agent 的'集体记忆'。当算法 Agent 更新了接口文档，前端 Agent 会自动感知到变化。这是传统知识库做不到的。"

**互动点**：点击"@Agent 整理"按钮，展示 AI 整理知识库的弹窗

### 第三步：Agent 协作（5 分钟）— 重点

**要讲什么**：
- 展示 4 个 Agent 的拓扑：产品、前端、后端、算法
- 逐条讲解 Agent 之间的对话记录，展示自动协作过程
- 重点讲解**人工确认节点**：Agent 自动完成了接口对齐、缓存策略、数据结构设计，但有两个决策需要产品确认

**关键话术**：
> "你看这个对话流，产品 Agent 拆解了需求，前端 Agent 提了展示方案，后端 Agent 设计了接口，算法 Agent 给出了延迟预估。它们自动完成了 90% 的沟通工作，最后只需要人确认两个关键决策。这就是'人指挥 Agent 团队'的工作方式。"

**互动点**：
- 点击"模拟协作"按钮，展示 Agent 节点逐个激活的动画
- 点击"确认全部"按钮，展示决策确认弹窗

### 第四步：部署与验证（3 分钟）

**要讲什么**：
- 展示流水线：代码提交 → AI 代码审查 → 单元测试 → 构建部署 → 性能验证 → 人工确认
- 展示性能指标对比表，Agent 自动生成了部署报告
- 有一个"需要人工确认"的警告（内存增加 5%）

**关键话术**：
> "传统部署是人驱动的：人提交代码、人跑测试、人看指标、人点发布。这里是 Agent 驱动的：后端 Agent 和算法 Agent 协作完成了部署，测试 Agent 自动跑回归，最后只需要人确认性能指标是否达标。人的角色从'操作者'变成了'决策者'。"

**互动点**：点击"模拟部署"按钮，展示流水线步骤动画

### 第五步：权限管理（2 分钟）

**要讲什么**：
- 展示三层权限模型：本地私密、团队共享、角色限制
- 展示角色权限矩阵和 Agent 权限控制

**关键话术**：
> "权限控制是团队版的基础。不只是人的权限，还有 Agent 的权限。比如产品 Agent 可以写知识库但不能部署，后端 Agent 可以部署但不能改产品文档。这样团队才能信任 Agent 自主操作。"

### 第六步：收尾 — 与 Qoder 的契合（3 分钟）

**回到 Qoder 当前方向**：
- "理解目标、拆任务、交付结果" → 我延伸为"团队目标拆解、多 Agent 协作、自动交付"
- "指挥一组 AI" → 我延伸为"每个人指挥自己的 Agent，Agent 之间自动协作"

**为什么是 Qoder 做这件事**：
- Qoder 在代码理解和 Agent 能力上有积累，这是其他协作工具（Notion、飞书）做不到的
- Qoder 已经有 Teams 版的基础，团队版是自然延伸
- 开发者是最早采纳者，但"一人公司"和"小团队"是更大的市场

## 面试常见问题准备

**Q：这个 Demo 是你一个人做的吗？**
> "是我设计的。我用 QoderWork 帮我生成了 HTML 原型代码。这本身就是我想展示的点——AI 可以帮产品经理快速把想法变成可交互的原型。"

**Q：Qoder 现在只做开发者，你想做团队协作，会不会太发散？**
> "不是发散，是延伸。Qoder 的核心能力（AI 理解目标并交付）是通用的。开发者是最早采纳者，但一旦'多 Agent 协作'的能力跑通，它天然适合团队场景。我的方案是分阶段的：先做开发者单人 Agent，再做团队知识库，再做 Agent 协作，最后做自动部署。"

**Q：和 GitHub Copilot Workspace、Cursor 有什么区别？**
> "GitHub Copilot 的本质是'辅助'，Cursor 的本质是'更好的 IDE'。Qoder 的方向是'AI 交付结果'。团队协作版是在这个方向上更进一步——不只是一个人和 AI 对话，而是多个 Agent 自动协作、人做决策。这个方向 GitHub 和 Cursor 都没有做。"

**Q：Agent 之间怎么知道对方在做什么？怎么避免冲突？**
> "这就是产品的核心设计。我在 Demo 里展示了 Agent 对话记录，这就是 Agent 之间的'沟通协议'。每个 Agent 的输入输出都记录在案，其他 Agent 可以感知到。冲突检测是 Agent 编排层的核心能力，比如两个 Agent 同时改同一个接口，编排层需要发现并解决冲突。"

**Q：如果 Agent 做错了怎么办？**
> "这就是为什么我在每个关键节点都设计了'人工确认'。Agent 自动完成 90% 的工作，但关键决策（部署、接口变更、数据操作）需要人拍板。这不是 Agent 能力不够，而是产品设计上要建立信任。"
