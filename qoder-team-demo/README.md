Qoder 团队版 Demo - 产品设计说明
===================================

## 产品定位

**一句话描述**：Qoder Team 是一个让多人 + 多 AI Agent 协同工作的桌面级协作平台，从"个人 AI 助手"升级为"团队 AI 协作引擎"。

**核心价值主张**：
- 让团队里的每个人都有自己的 AI Agent
- Agent 之间能理解、沟通、协作
- 人从"写代码的人"变成"指挥团队的人"

---

## 用户故事

**场景 1: 多人协作维护知识库（初版核心）**
> 作为一名算法工程师，我希望和团队成员共同维护一个项目知识库，这样我们可以共享代码片段、API 文档和最佳实践。

**场景 2: 跨角色 Agent 协作（长期愿景）**
> 作为一名产品经理，我希望我的产品 Agent 能和前端 Agent、后端 Agent 自动沟通需求，这样我不需要反复开会同步。

**场景 3: 自动部署与验证（长期愿景）**
> 作为一名工程负责人，我希望代码完成后自动部署、跑测试、做性能监控，这样我只需要确认最终结果。

**场景 4: 权限与访问控制（初版核心）**
> 作为一名团队成员，我希望本地文件保持私密，团队文件可以共享，这样既能保护个人隐私又能高效协作。

---

## Demo 设计的 4 个页面

**页面 1: 工作台首页**
- 展示"本地空间"（私密）和"团队空间"（共享）
- 快速入口：创建新知识库、邀请团队成员、查看 Agent 协作记录

**页面 2: 团队知识库**
- 可协作编辑的文档/代码片段
- 显示贡献者、更新时间、版本历史
- 支持 @Agent 让 AI 帮忙整理或搜索

**页面 3: Agent 协作面板**
- 展示不同角色的 Agent（产品 Agent、前端 Agent、后端 Agent、算法 Agent）
- Agent 之间的对话记录
- 任务流转状态（等待中/进行中/已完成/需人工确认）

**页面 4: 部署与验证看板**
- 自动部署状态
- 测试结果
- 性能指标
- 人工确认按钮

## 与 Qoder 当前方向的契合点

**Qoder 现在在做**：让 AI 不只是补全代码，而是理解目标、拆任务、交付结果

**团队版的延伸**：
- "理解目标" → 产品 Agent 理解业务目标，拆解为用户故事
- "拆任务" → 任务自动分配给对应的 Agent（前端、后端、算法）
- "交付结果" → 自动部署、验证、人工确认
- "指挥一组 AI" → 团队里的每个人指挥自己的 Agent，Agent 之间自动协作

## 面试时的讲解思路

1. **开场**：先讲我对 Qoder 产品方向的理解（Agentic Coding 的延伸空间）
2. **展示 Demo**：边操作边讲解 4 个场景
3. **讲契合点**：为什么这个方向适合 Qoder（不是其他产品）
4. **讲实施路线**：初版做什么、长期做什么、为什么这样规划
5. **收尾**：回到产品经理的核心能力——理解用户、定义问题、设计方案
